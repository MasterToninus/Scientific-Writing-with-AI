# Build the controlled scientific agent

Read the [toolkit instructions](../../../AGENTS.md), [builder guide](../../../AI/AGENTS.md) and [project-packet guide](../../../AI/README.md). Use the working worksheet and subsequent human clarifications as evidence; use the [scientific-agent template](../../../AI/AGENTS.template.md) as the starting structure.

## Translate decisions into operational rules

- Reconcile the actual answers by activity ID, retaining scope, conditions, human authority and unresolved cases. Preserve the complete decision register rather than listing only allowed activities.
- A provisional packet may contain explicit unknowns or labelled proposals. Do not convert them into permissions, invented defaults or claims of shared adoption.
- Keep the builder's broad preparation autonomy separate from the generated agent's scientific permissions. The generated agent asks when a relevant `?` arises and cannot change its own permissions to unblock a task.
- Make tool/skill access, underlying scientific activities and external operations distinct. An approved skill cannot authorise a prohibited or unresolved operation; record the agreed skill inventory and maintenance rules.
- Generate one canonical project `AGENTS.md`. A `CLAUDE.md` bridge should load that same policy rather than duplicate or relax it. Keep the bridge and paths consistent with the actual output layout.
- Instantiate the agreed documentation in a separate project location, normally `AI/generated/<project>/`. Update filenames and links together. Keep the reusable templates blank.
- Populate the initial activity row only for actual packet creation. Distinguish observed use from human reports; keep unknown dates, models and first-effect hashes explicit. Derive disclosure text from evidence, not from the permission list.

## Check the packet

Check agreement-to-rule consistency, unresolved conditions, relative links, instruction bridges and actual setup facts. Keep changes proportionate to human review. Report the packet's status and remaining adoption-critical decisions without claiming manuscript integration or disclosure approval.

Use the [integration guide](../../../INTEGRATION.md) only when installation into the separate manuscript project is requested within its actual authority.
