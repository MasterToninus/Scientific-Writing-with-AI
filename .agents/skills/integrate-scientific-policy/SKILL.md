# Integrate the adopted scientific policy

Read the [toolkit instructions](../../../AGENTS.md) and [integration guide](../../../INTEGRATION.md). Identify the target project's applicable instructions and the requested adopted packet before changing that project.

## Resolve the actual scope

Establish the target, reported agreement, repository-access scope and operations already authorised. A request may cover several operations; do not ask again for authority already given. If an adoption-critical fact is missing, prepare the concrete comparison and ask about that fact before dependent installation.

## Integrate without broadening the task

- Inspect the target's existing instructions, AI records, local changes and staging. Reconcile compatible material without erasing history or unrelated work.
- Install the project-specific controlled `AGENTS.md`, its agreed documentation and the matching `CLAUDE.md` bridge where applicable. Do not copy the toolkit builder instructions or builder skills into the manuscript.
- Introduce project skills only within the reported policy and requested setup. Use the approved inventory; keep every underlying operation subject to the scientific agent's permissions.
- Preserve existing scientific content, bibliography, figures, macros and source headers during initial policy-only integration. Source adaptations, including inserting the tentative disclosure, are separate tasks.
- Verify links, actual instruction loading and any in-scope build checks. A source file or a successful template compilation does not prove integration in the target environment.
- Handle staging, commits and publication only within the actual request and target policy. Use the applicable provenance tag and preserve unrelated history. Where W15 uses hashes, leave new effects PENDING; during the next otherwise-needed authorised AI-prepared commit, complete eligible earlier rows with the verified original first-effect SHA as described in the integration guide. Do not create or request a dedicated metadata commit, amend for a self-hash, or make immediate post-commit hash-only edits.

## Leave an accurate handoff

Report installed files, checks actually performed, unresolved setup and any remaining local changes. Distinguish policy adoption, installation, successful instruction loading, scientific verification and disclosure approval. If a concrete conflict arises, stop the affected operation and explain the choice needed while continuing independent authorised work.
